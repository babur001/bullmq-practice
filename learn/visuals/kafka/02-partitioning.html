Which partition does a record land in — and why that one?

Every keyed record's home is decided by one deterministic computation — the same murmur2 hash the real broker runs. Trace it here, then watch records snap into a partition's next offset.

keyed — pinned by hash % N keyless — sticky partitioner repartition — routing changed
Read each tape top-to-bottom. Offsets only climb — that strict per-partition order is the only ordering Kafka guarantees; across tapes there is none. A key nails every record with that key to one tape, so user-A's login→checkout→pay stay in order. No key lets the sticky partitioner fill one tape per producer batch, then move on — even spread, no cross-tape order. Now switch partitions 3→4→6 and re-route the same key: it jumps tapes. That's why growing a topic's partition count re-homes keys and breaks their in-flight order — Kafka makes you do it on purpose.
